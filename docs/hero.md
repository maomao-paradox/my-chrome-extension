## 项目概述

构建一个 React + Vite 单页网站，核心体验为「滚轮驱动的一日循环 3D 场景」：页面滚动进度从 0% 到 100% 映射到一天中 7:00 至次日 7:00 共 24 小时。场景为 3D 公园一角（长椅、树、鸟），太阳/月亮沿弧线运行，整体色彩与光照随时间变化。此前的像素点网格背景可作为场景远景/天空层点缀保留，或替换为天空渐变层。

### 技术栈
React 18 + Vite + TypeScript

Three.js + @react-three/fiber + @react-three/drei

GSAP + ScrollTrigger（滚动进度 → 时间映射）

Lenis（平滑滚动，让时间推进更顺滑）

Framer Motion（UI 文字/提示动画）

Tailwind CSS（界面覆盖层样式）

### 核心时间系统
```text
scrollProgress (0 → 1)  →  timeOfDay (7:00 → 次日 7:00)
timeOfDay 归一化为 t ∈ [0, 1]，0 = 7:00，1 = 次日 7:00
所有场景状态（天体位置、光照、颜色、雾、星星透明度）均为 t 的纯函数
页面总高度设为约 600vh–800vh，给足滚动空间


用 GSAP ScrollTrigger 将滚动进度写入全局状态（如 Zustand 或 Context），3D 场景每帧读取

提供时间显示 UI（如 "14:32"），随滚动实时更新，可固定在角落

支持 prefers-reduced-motion：改为分段静态快照或降低过渡频率
```

### 天象系统
太阳：

可见时段约 7:00–19:00（t 约 0–0.5）

从屏幕左侧地平线升起，沿弧线（半圆或椭圆弧）经过上方，到右侧地平线落下

位置由 t 驱动：角度 θ = π * (t / 0.5)，x、y 按弧线计算

夜晚段移出画面（y 低于地平线）或渐隐

月亮：

可见时段约 19:00–次日 7:00（t 约 0.5–1）

轨迹与太阳类似但错开，弧线可略低，颜色冷白

与太阳交替出现，交界时段做淡入淡出

星星：

夜间渐显（t 约 0.5–1 期间透明度升高），白天渐隐

在天空层随机分布，可做轻微闪烁/缓慢漂移

用 Points 或 InstancedMesh 实现，性能友好

光照与色彩系统
主光源 DirectionalLight 跟随太阳（白天）或月亮（夜晚）位置，阴影方向与长度随之变化

环境光强度、色温随时间曲线变化

天空背景使用渐变（可用 shader 或大球体），颜色关键帧：

7:00 清晨暖橙粉

12:00 明亮白蓝

18:00 黄昏橙红紫

0:00 深夜蓝黑

6:00 黎明青蓝渐暖

雾效颜色与浓度随时间变化，增强氛围

建议用颜色关键帧数组 + 插值函数统一管理，避免散落硬编码

### 场景元素
长椅：场景中央偏下，3D 模型（可用基础几何体拼搭或 GLB），随光照产生阴影

树：长椅旁，树干 + 树冠（树冠可用多层几何或实例化叶片），支持轻微摆动（顶点着色器或简单旋转），叶影投在地面

鸟：地上 2–4 只，做细微动作（啄食、转头、偶尔小跳/飞起），可用简单几何体组合 + 关键帧动画

地面：接收阴影的平面，材质随光照变化

相机基本固定（可随滚动有极轻微推拉/俯仰增强层次），保证叙事焦点稳定

像素点网格背景（可选保留）
若保留此前的像素点网格作为天空层点缀：

作为远景层，位于天空渐变之上、场景元素之下

仍保留鼠标悬浮起伏效果

网格亮度/透明度可随时间变化（夜间更明显，白天更淡）

与时间系统解耦，仅作氛围点缀

### 工程结构（建议）
```text
page/hero/
  components/
    Scene.tsx              // 3D 场景根
    TimeOverlay.tsx        // 时间显示 UI
    PixelGridBackground.tsx
  scenes/
    Sky.tsx                // 天空渐变 + 星星
    Sun.tsx
    Moon.tsx
    Park.tsx               // 长椅 + 树 + 鸟 + 地面
    Lights.tsx             // 光照随时间驱动
  systems/
    timeMapping.ts         // scrollProgress → t → 各状态
    colorKeyframes.ts      // 天空/雾/光照颜色关键帧与插值
  hooks/
    useScrollProgress.ts
    useTimeOfDay.ts
  store/
    useTimeStore.ts        // 全局时间状态
  App.tsx
  main.tsx
```
### 性能与体验
3D 场景 lazy 加载 + Suspense

星星、叶片等大量重复元素用 InstancedMesh 或 Points

所有随时间变化的状态用 lerp 平滑，避免滚动抖动导致跳变

阴影贴图分辨率适中，移动端可降级关闭部分阴影

响应式适配移动端（触摸滚动驱动时间）

目标 60fps

### 交付要求
完整可运行工程，含 npm scripts

README 说明时间映射逻辑、颜色关键帧配置、如何调整节奏

代码注释关键时间/颜色/天象计算逻辑

## 拆解

### 分阶段实现清单 · 滚轮驱动一日循环 3D 公园场景

> 配合前面的完整工程提示词使用。每个阶段都可独立运行、可验证，按顺序推进。每阶段末尾给出「验收标准」，AI 助手每完成一个阶段应先自测再进入下一阶段。

---

### 阶段 0 · 工程初始化

**目标**：搭好空壳工程，跑通开发环境。

**任务**
- 用 Vite 创建 React + TS 工程
- 安装依赖：three、@react-three/fiber、@react-three/drei、gsap、lenis、framer-motion、zustand、tailwindcss
- 配置 Tailwind、ESLint/Prettier
- 建立目录骨架（components / scenes / systems / hooks / store）
- 根组件放置一个全屏 `<Canvas>`，渲染一个占位立方体 + 旋转动画，验证 R3F 可用

**验收标准**
- `npm run dev` 启动无报错
- 屏幕上出现持续旋转的立方体
- 构建 `npm run build` 通过

---

### 阶段 1 · 滚动 → 时间系统（核心地基）

**目标**：跑通「滚轮进度 → 24 小时时间」的映射，暂时只用 UI 显示，不涉及 3D。

**任务**
- 创建 `useTimeStore`（Zustand）：存 `scrollProgress`（0–1）与派生 `timeOfDay`
- 页面设置总高度（如 700vh），用一个占位长滚动容器
- 用 Lenis 接管平滑滚动
- 用 GSAP ScrollTrigger（或 Lenis 回调）把滚动进度写入 store
- 实现 `timeMapping.ts`：`progress → t(0–1) → 小时/分钟字符串`
- 创建 `TimeOverlay`：固定在角落显示当前时间（如 "14:32"），随滚动实时更新
- 处理 `prefers-reduced-motion`

**验收标准**
- 滚动页面时角落时间从 07:00 平滑走到次日 07:00
- 滚到底时间正好是次日 07:00，滚到顶正好 07:00
- 快速滚动/反向滚动时间连续、无跳变
- 减少动态模式下仍可用（可降频）

---

### 阶段 2 · 天空与天体

**目标**：天空渐变 + 太阳/月亮沿弧线运行 + 星星夜间显现。

**任务**
- `Sky.tsx`：全屏天空背景（大球体 + 渐变 shader 或分层渐变），接受 `t` 参数
- `colorKeyframes.ts`：定义天空颜色关键帧（7 点暖橙粉 / 12 点白蓝 / 18 点橙红紫 / 0 点蓝黑 / 6 点青蓝暖），实现插值函数
- `Sun.tsx`：位置由 `t` 驱动，7:00–19:00 从左侧地平线沿弧线到右侧落下；颜色/光晕随高度变化
- `Moon.tsx`：19:00–次日 7:00 沿弧线运行，与太阳交替淡入淡出
- `Stars.tsx`：Points 实现，夜间透明度渐显、白天渐隐，轻微闪烁
- 所有天体位置/透明度必须是 `t` 的纯函数，用 lerp 平滑

**验收标准**
- 滚动时太阳从左升、划过顶部、右侧落下，轨迹为弧线
- 白天结束太阳淡出、月亮淡入，夜晚月亮走弧线
- 星星只在夜间可见，昼夜交界平滑过渡
- 天空颜色随时间连续变化，无突兀跳色

---

### 阶段 3 · 光照与氛围

**目标**：光照方向/强度/色温、雾效随时间联动，让昼夜氛围成立。

**任务**
- `Lights.tsx`：DirectionalLight 位置跟随太阳（白天）或月亮（夜晚），阴影方向与长度随之变化
- 环境光强度、色温按时间曲线变化
- 雾效颜色与浓度随时间变化
- 引入一个接收阴影的地面占位平面，验证阴影随光源变化
- 颜色/强度关键帧统一放 `colorKeyframes.ts`，与天空共用插值工具

**验收标准**
- 正午阴影短、清晨黄昏阴影长且方向反转
- 夜晚整体转冷调偏暗，月光下仍有可辨识阴影
- 雾/氛围颜色与天空协调，昼夜过渡自然
- 地面阴影跟随光源正确变化

---

### 阶段 4 · 场景元素

**目标**：加入长椅、树、鸟，形成完整公园一角。

**任务**
- `Park.tsx`：组装地面、长椅、树、鸟
- **长椅**：基础几何体拼搭或 GLB，置于中央偏下，投射/接收阴影
- **树**：树干 + 树冠（多层几何或实例化叶片），轻微摆动（顶点着色器或简单旋转），叶影投地
- **鸟**：地上 2–4 只，简单几何组合 + 关键帧做啄食/转头/偶尔小跳或飞起
- **相机**：基本固定，可随滚动做极轻微推拉/俯仰增强层次
- 所有元素材质随光照响应（PBR 材质 + 环境光）

**验收标准**
- 场景中有长椅、树、鸟，构图聚焦、比例协调
- 树有轻微摆动，鸟有细微动作，不喧宾夺主
- 元素随昼夜光照正确明暗变化，阴影正确
- 滚动时相机有轻微层次变化但不影响叙事焦点

---

### 阶段 5 · 氛围打磨与点缀

**目标**：整体观感打磨，加入可选像素网格点缀与细节。

**任务**
- （可选）`PixelGridBackground.tsx`：作为远景/天空层点缀，保留鼠标悬浮起伏；亮度随时间变化（夜显昼淡），与时间系统解耦
- 加入氛围细节：光晕、镜头微光、夜间地面反光、鸟飞起时的小粒子等（按需选择，克制）
- 时间 UI 视觉打磨（字体、淡入淡出、昼夜配色切换）
- 入场动画（Framer Motion）：标题/提示分层入场
- 滚动提示（如"向下滚动推进时间"）首次出现后淡出

**验收标准**
- 整体画面协调，昼夜氛围完整
- 点缀元素不干扰主体、性能不掉帧
- UI 与场景风格统一，有清晰操作提示
- 首次进入体验完整

---

### 阶段 6 · 性能、响应式与交付

**目标**：可上线、可维护、可交付。

**任务**
- 性能：3D 场景 lazy + Suspense；星星/叶片 InstancedMesh/Points；阴影分辨率按设备降级；移动端关闭部分阴影
- 响应式：移动端触摸滚动驱动时间；相机视野与构图适配竖屏
- 无 WebGL/低端设备降级方案（静态快照或简化场景）
- 资源压缩（GLB/纹理/WebP）
- README：时间映射逻辑、颜色关键帧配置、节奏调整方法、目录结构、启动方式
- 关键代码注释（时间/颜色/天象计算）
- 最终自测：全流程滚动、反向滚动、快速滚动、移动端、reduced-motion

**验收标准**
- 桌面与移动端均 60fps 流畅
- 全流程滚动体验完整、无跳变无报错
- `npm run build` + `preview` 正常
- README 完整，他人可依文档调整节奏与配色
- 低端/无 WebGL 有可用降级

### 推进约定（给 AI 助手）

- 每个阶段完成后先输出「本阶段改动 + 验收自测结果」，确认通过再进行下一阶段
- 所有随时间变化的状态统一走 `t` 纯函数 + lerp，禁止散落硬编码魔法数
- 颜色/强度关键帧集中在 `colorKeyframes.ts`，便于后续调参
- 阶段 2–4 期间保持 `TimeOverlay` 可见，作为时间系统的可视化校验
- 每阶段结束运行一次 `npm run build` 确保无类型/构建错误
